# Tesseract мовні моделі (tessdata)

Моделі розпізнавання тексту для OCR сканів і фото накладних
(`apps/api/src/modules/xlsx/ocr-text-layer.provider.ts`).


## Чому `tessdata_fast`, а не `tessdata` / `tessdata_best`

`fast` — int8-квантовані LSTM-моделі: удвічі менші й помітно швидші за `best` при незначній втраті
точності на друкованому тексті. Для накладних (чіткий друк, не рукопис) цього достатньо, а розмір
і час критичні: моделі їдуть усередині Docker-образу в офлайн-інсталяторі, а розпізнавання
відбувається синхронно, поки користувач чекає.

## Чому обидві мови

Накладні українські, але **артикули — латиницею**. На `ukr` самій tesseract плутав латиницю з
кирилицею (`WL7129` → `М/. 7129`, `GSP-9025` → `ОЗР-9025`). З `ukr+eng` ці артикули розпізнаються
точно. Провайдер завжди вантажить обидві мови разом.

## Чому файли в git, а не завантаження на етапі збірки

**Офлайн-незалежність (ADR-001, ADR-003).** Завантаження під час `docker build` означало б, що без
інтернету не збирається реліз, не проходять тести після `git clone`, а зникнення upstream-тегу ламає
відтворюваність історичних збірок. 7.7 МБ незмінних бінарників — прийнятна ціна.

Git LFS не використовуємо: у проєкті його немає, і заводити його заради двох файлів — більше
операційної складності (LFS-сервер, квоти, `git lfs install` у CI), ніж користі.

## Як потрапляють у прод

`apps/api/Dockerfile` копіює весь каталог `assets/` у runner-стадію → моделі всередині образу
`sto-api` → `docker save` у `.tar.gz` → офлайн-інсталятор. **Змін в `installer/` не потрібно.**

Шлях у рантаймі резолвить `resolveTessdataDir()`; перевизначається змінною `OCR_TESSDATA_PATH`.
