## Збереження рядків документа кількома запитами: повтор після збою (2026-10-30)

- [ ] Картка зберігає рядки серією запитів (POST нових → PATCH змінених → DELETE прибраних) →
      рядок, який `POST` уже створив, отримує у формі `id` з відповіді й іде в набір «було на
      сервері» (`initialLineIdsRef`). Лише «пропускати на повторі за `_key`» (Bug #755) мало:
      якщо після збою користувач прибере цей рядок, повтор його не видалить — сирота на сервері,
      якої картка не показує. І навпаки: щойно створені `id` входять у «поточні» того ж проходу,
      інакше той самий «Зберегти» їх одразу ж видаляє (знімок рядків зроблено до POST). Тест:
      POST → збій далі → прибрати новий рядок → повтор шле `DELETE <новий id>`, а перший прохід —
      ні. Grep: `grep -n "postedLineKeysRef\|initialLineIdsRef" apps/web/src -r`
- [ ] **UI-блокування правила «не зняти X» вимикає контрол лише для ЗБЕРЕЖЕНОГО X.** Сервер забороняє
      один напрям (`isCash: false` для `cash`); прапорець, вимкнений за кодом способу, не дає й повернути
      ознаку запису, з якого її зняли до правила. Умова — `code === … && saved.flag`, не лише код
      (`journal/web.md`, 2026-10-31)
