# ADR-012: Унікальні секрети на інсталяцію + аварійне відновлення

**Дата:** 2026-06-05
**Статус:** Прийнято
**Автор:** Максим Козловський
**Залежить від:** ADR-001 (offline-first), ADR-002 (Docker Compose), ADR-003 (installer)
**Закриває:** G1, G2, G12 (GAPS.md)

## Контекст

Дві суміжні критичні прогалини, виявлені при огляді архітектури:

- **G2 — секрети.** Якщо `JWT_ACCESS_SECRET`, паролі PostgreSQL і ключі MinIO однакові в усіх інсталяцій (зашиті в образ чи git), один витік компрометує всіх клієнтів.
- **G1 / G12 — відновлення.** `Backup.ps1` робить копії, але локально, на тому ж сервері. Втрата диска, ransomware або крадіжка сервера = втрата всього бізнесу клієнта. Відновлення не протестоване.

Обидві блокують комерційний запуск і вирішуються разом, бо бекап містить секрети.

## Драйвери рішення

- Ізоляція компрометації: проблема однієї інсталяції не зачіпає інших.
- Виживання бізнесу клієнта при катастрофі (диск, ransomware, крадіжка).
- Приватність (ADR-001): дані не покидають сервер у відкритому вигляді.
- Не порушити офлайн-незалежність: off-site backup — опційний, локальна робота не залежить від нього.

## Рішення

### Частина A — Унікальні секрети на інсталяцію

1. **Генерація при першому запуску.** Setup-майстер генерує криптографічно випадкові секрети **на цій машині**, не зашиті в образ і не в git:
   `POSTGRES_PASSWORD`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, внутрішні service-токени.
2. **Зберігання.** Запис у `.env` з обмеженими правами доступу (ACL лише для служби), поза образом і поза репозиторієм.
3. **Жодних дефолтів.** Setup не дозволяє слабкі/типові паролі; немає вшитих стандартних значень.
4. **Публічний ключ ліцензії** (ADR-008) — спільний для всіх (він публічний, це нормально). Приватний ключ — тільки на Hub.
5. **Ротація.** Скрипт перегенерації JWT-секретів (інвалідує активні сесії) на випадок підозри на витік.

### Частина B — Аварійне відновлення (DR)

1. **Три рівні бекапу:**
   - **Локальний** (`Backup.ps1`, уже є) — швидке відновлення, ротація 30 днів.
   - **Off-site зашифрований** (новий, рекомендований) — копія у хмару клієнта (його обліковий запис: S3 / Google Drive / Hub opt-in) через `rclone`. Захист від втрати заліза, ransomware, крадіжки.
   - **Immutable / versioned** — off-site копія версіонована з окремими write-only креденшелами, щоб ransomware не перезаписав історію.
2. **Шифрування перед виходом за межі сервера.** Backup шифрується на клієнті (`age` / GPG) до вивантаження — приватність (ADR-001). Ключ відновлення зберігає власник; **escrow на Hub** — опційно (щоб не втратити доступ).
3. **Цілі:** RPO ≤ 6 год (частота бекапу), RTO ≤ 1–2 год (час відновлення).
4. **Перевірені відновлення.** `Restore.ps1` + перевірка цілісності (checksum + тест-відновлення у тимчасовий контейнер) + щоквартальний drill на чисту VM. Документована покрокова процедура для адміна.
5. **Офлайн-сайти.** Якщо немає каналу для off-site — лишається локальний бекап + ручний експорт зашифрованого архіву на USB.

### Потік

```
Backup.ps1 v2:
  pg_dump + mc mirror MinIO + .env(зашифрований)
  → Compress-Archive → age encrypt → checksum
  → локально (ротація 30д) + rclone → off-site (versioned)

Restore.ps1:
  download → checksum → age decrypt
  → restore DB + MinIO → prisma migrate deploy → health-check
```

## Наслідки

### Позитивні

- Один витік не валить усіх інсталяцій (унікальні секрети).
- Бізнес клієнта виживає при втраті заліза / ransomware / крадіжці.
- Бекап зашифрований — приватність даних клієнтів збережена.

### Негативні та їх вирішення

- **Off-site потребує місця/каналу** → опційний; для офлайн-сайтів — локальний + USB.
- **Ризик втрати ключа шифрування** → escrow на Hub (opt-in) + чітке попередження власнику.
- **Складніший setup** (генерація секретів) → автоматизовано в майстрі, прозоро для користувача.

### Ризики

- Власник втратив ключ відновлення і не ввімкнув escrow → off-site backup не відновити. Пом'якшення: явне попередження + рекомендований escrow.
- Дефолтні секрети «протекли» зі старих білдів → CI-перевірка (S6) забороняє секрети/дефолти в образах і git.

## Тригер перегляду

- Якщо клієнти масово не вмикають off-site → зробити мінімальний безкоштовний off-site через Hub за замовчуванням (opt-out).
