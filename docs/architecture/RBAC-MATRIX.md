# STO ERP — RBAC Матриця доступу

> Авторитетне джерело прав для кожної ролі. Claude Code читає цей файл при генерації `@Roles()` декораторів та guard-перевірок.

---

## Ролі системи

| Роль | Опис | Типовий користувач |
|------|------|-------------------|
| `OWNER` | Власник СТО. Повний доступ | Директор / власник бізнесу |
| `ADMIN` | Адміністратор. Майже повний доступ, крім деяких фінансових операцій | Старший менеджер |
| `RECEPTIONIST` | Приймальник. Робота з клієнтами та нарядами | Адміністратор стійки |
| `MECHANIC` | Механік. Робота зі своїми операціями | Технічний спеціаліст |
| `STOREKEEPER` | Комірник. Управління складом | Відповідальний за склад |
| `ACCOUNTANT` | Бухгалтер. Фінансові звіти та взаєморозрахунки | Бухгалтер / фінансист |

> **CLIENT** — зарезервована роль для майбутнього клієнтського порталу (Phase 5+). Наразі не реалізовується.

## Реалізація в NestJS

```typescript
// apps/api/src/auth/guards/roles.guard.ts
// Порівнювати роль з масивом дозволених

// Ієрархія ролей (вищі включають права нижчих):
const ROLE_HIERARCHY = {
  OWNER: ['OWNER', 'ADMIN', 'RECEPTIONIST', 'MECHANIC', 'STOREKEEPER', 'ACCOUNTANT'],
  ADMIN: ['ADMIN', 'RECEPTIONIST', 'MECHANIC', 'STOREKEEPER', 'ACCOUNTANT'],
  RECEPTIONIST: ['RECEPTIONIST'],
  MECHANIC: ['MECHANIC'],
  STOREKEEPER: ['STOREKEEPER'],
  ACCOUNTANT: ['ACCOUNTANT'],
};

// Приклад використання в контролері:
@Roles('RECEPTIONIST', 'ADMIN', 'OWNER')  // будь-яка з цих ролей
async createWorkOrder(...) {}

@Roles('OWNER')  // тільки OWNER
async deleteOrganisation(...) {}
```

## Важливі зауваження

1. **orgId isolation** — кожен запит фільтрується по `orgId`. Роль не замінює tenant isolation.
2. **Власні записи (🔒)** — механік бачить тільки WorkOrderLine де `employeeId = currentUser.id`
3. **⚠️ Підтвердження** — операції позначені ⚠️ потребують подвійного підтвердження в UI або PIN-коду
4. **Фінансові операції** — RECEPTIONIST може проводити платіж, але не може редагувати транзакції після запису
5. **Аудит** — всі зміни з OWNER/ADMIN правами логуються в окрему audit_log таблицю (Phase 2)
