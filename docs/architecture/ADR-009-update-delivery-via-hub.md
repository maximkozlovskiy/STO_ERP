# ADR-009: Доставка оновлень через Cloud Hub

**Дата:** 2026-06-05
**Статус:** Прийнято
**Автор:** Максим Козловський
**Залежить від:** ADR-002 (Docker Compose), ADR-006 (Cloud Sync Hub), ADR-007 (механіка оновлення), ADR-008 (ліцензування + heartbeat)

## Контекст

ADR-007 вирішив **механіку застосування** оновлення на одній інсталяції (`Update.ps1`: backup → pull → `prisma migrate deploy` → health-check → rollback). Чого він **не** вирішує:

1. **Звідки** офлайн-СТО беруть нові образи, якщо інтернет нестабільний або відсутній.
2. **Як централізовано керувати** тим, кому й коли прилітає оновлення.
3. **Поетапність** розгортання, щоб поганий реліз не поклав усіх клієнтів одночасно.
4. **Телеметрію версій** — хто на чому сидить, де оновлення провалилось.
5. **Зв'язок із підпискою** — оновлення як важіль монетизації.

Cloud Hub (ADR-006/008) уже існує в плані як ліцензійний сервер і вже отримує **heartbeat із версією інсталяції**. Тому той самий сервіс природно стає сервером оновлень — без дублювання інфраструктури.

## Драйвери рішення

- Не порушити офлайн-незалежність (правила ядра №1–3): оновлення ніколи не зупиняє роботу.
- Перевикористати Hub і PKI ліцензій (ADR-008), а не будувати окрему систему.
- Безпечні релізи при зростанні кількості клієнтів (поетапність + автостоп).
- Підтримати як онлайн-, так і повністю офлайн-сайти.

## Розглянуті варіанти доставки образів

### Варіант A: Прямий pull з container registry (ghcr.io)

Як припускав ADR-007. **Мінус:** потребує стабільного інтернету на СТО; немає телеметрії й керування розкаткою.

### Варіант B: Доставка через Cloud Hub (обрано) ✅

Hub роздає підписані бандли, бачить версії всіх інсталяцій через heartbeat, керує розкаткою.
**Плюс:** єдиний сервіс (ліцензії + оновлення + телеметрія), повний контроль.
**Мінус:** Hub стає критичним для доставки (але не для роботи СТО).

### Варіант C: Офлайн-бандл / USB

Підписаний `.zip`/`.exe` для сайтів без інтернету.
**Роль:** вторинний канал поряд із B (не основний, але обов'язковий для офлайн-сайтів).

## Рішення

### 1. Hub = сервер оновлень + телеметрія

Heartbeat (ADR-008) несе `currentVersion`, `channel`, `lastUpdateStatus`. У відповідь Hub повертає **update-manifest**:

```
{ latestVersion, channel, requireConfirm, downloadUrl,
  sha256, signature, mandatorySecurity }
```

### 2. Канал доставки — через Hub + офлайн-бандл

- **Основний:** Hub роздає підписані бандли образів `api` + `web`.
- **Офлайн-сайти:** адмін завантажує підписаний бандл із кабінету Hub (коли є зв'язок) або приносить на USB → `Update.ps1 --bundle <file>`.
- Registry лишається лише як внутрішній build-артефакт CI, не як канал для клієнтів.

### 3. Тригер — гібридний

- **PATCH / security-фікси** → авто вночі через Task Scheduler (як у ADR-007).
- **MINOR / MAJOR** → банер «Доступне оновлення» в ERP; застосовується **після підтвердження адміна**. Прапорець `requireConfirm` задає Hub.

### 4. Поетапне розгортання (canary) + канали

- Hub призначає інсталяцію в **когорту**: 5% → 50% → 100%.
- **Health-gate:** наступна хвиля стартує, лише якщо success rate попередньої вище порога; інакше розкатка автоматично зупиняється.
- **Канали** `stable` / `beta` — охочі отримують реліз раніше (opt-in beta).

### 5. Цілісність — підпис релізів

Бандли підписані тим самим PKI, що й ліцензії (Ed25519 / cosign). `Update.ps1` перевіряє `sha256` **і** підпис перед `docker load`. Захищає від підміни образу при доставці через Hub чи USB.

### 6. Сумісність

- **Міграції БД** — forward-only за патерном **expand-contract** (нова схема сумісна зі старим кодом під час хвилі розкатки).
- **API версіонується** — старий мобільний клієнт (offline-first, WatermelonDB) лишається сумісним; мобільний оновлюється окремо через Expo OTA, не синхронно з API.

### 7. Прив'язка до підписки

- **Активна підписка** → manifest віддає останню версію свого каналу.
- **Прострочена** → Hub віддає лише останній **security-патч** поточної major-лінії; нові фічі заморожені. Робота не зупиняється.
- **Критичні security-фікси** (`mandatorySecurity = true`) → усім незалежно від статусу підписки.

### 8. Надійність

- Rollback із ADR-007 зберігається (backup → health 60с → відкат на попередні теги).
- Кожна інсталяція звітує результат оновлення на Hub (`UpdateEvent`), що живить health-gate і дашборд.

### 9. Телеметрія, дашборд, розсилки

- Hub показує розподіл версій, провалені оновлення, «застряглі» інсталяції.
- Розсилка адмінам СТО через `NotificationTemplate` + BullMQ: «доступне оновлення», «оновлення застосовано», «оновлення провалилось — відкат виконано».

## Потоки

**Онлайн-сайт:**

1. Heartbeat → Hub: `currentVersion`, `channel`, `lastUpdateStatus`.
2. Hub → manifest (остання версія для когорти й статусу підписки).
3. Якщо patch/security і авто → `Update.ps1` вночі: перевірка підпису → backup → `docker load` → `migrate deploy` → health 60с → ok / rollback → звіт на Hub.
4. Якщо minor/major → банер у ERP → адмін підтверджує → той самий потік.

**Офлайн-сайт:**

- Адмін завантажує підписаний бандл (кабінет Hub або USB) → `Update.ps1 --bundle <file>` → той самий перевірка/backup/health/rollback.

## Модель даних (нове, на Hub)

`ReleaseChannel`, `Release` (version, channel, imageRefs, sha256, signature, mandatorySecurity, notes), `RolloutCohort` / `RolloutWave`, `InstallationVersion` (з heartbeat), `UpdateEvent` (результат оновлення по інсталяції).

## Наслідки

### Позитивні

- Єдиний сервіс: ліцензії + оновлення + телеметрія.
- Безпечні поетапні релізи з автостопом при проблемах.
- Офлайн-сайти підтримані бандлом.
- Оновлення стають retention-важелем, без зупинки роботи СТО.

### Негативні та їх вирішення

- **Hub критичний для доставки** → але не для роботи СТО; офлайн-бандл як запасний канал.
- **Потрібен PKI підпису релізів** → спільний із ліцензіями (ADR-008).
- **Дисципліна expand-contract міграцій** → закласти в `/sto-database` чеклист.

### Ризики

- **Розмір бандлів** (повні образи 0.5–2.5 ГБ): розкочуємо лише `api` + `web` (postgres/redis/minio/caddy змінюються рідко), як уже робить `Update.ps1`; за потреби — дельта-шари Docker.
- **Годинник клієнта**: для перевірки термінів і черговості використовувати серверний час із heartbeat, не локальний.

## Тригер перегляду

- Якщо офлайн-сайтів стане багато → дзеркало / CDN бандлів.
- Якщо релізи стануть частими → дельта-оновлення образів замість повних.
