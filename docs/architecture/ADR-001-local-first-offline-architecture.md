# ADR-001: Local-First Offline Architecture

**Дата:** 2026-05-22
**Статус:** Прийнято
**Автор:** Максим Козловський

## Контекст

STO ERP призначений для автосервісів України. Більшість СТО мають нестабільне або взагалі відсутнє інтернет-з'єднання у виробничій зоні (бокси, ями). Механік на планшеті в боксі не може чекати, поки завантажиться API через хмару. Приймальник не може зупинити роботу через збій провайдера.

## Драйвери рішення

- Надійність: СТО повинна працювати 24/7 незалежно від стану інтернету
- Швидкість: відгук системи ≤ 100ms (локальна мережа vs 200–500ms хмара)
- Конфіденційність: дані клієнтів і фінансові дані зберігаються локально
- Вартість: немає щомісячних витрат на хмарний хостинг для основних функцій
- Регуляторика: дані не покидають приміщення без явної згоди власника СТО

## Розглянуті варіанти

### Варіант A: Cloud-Only SaaS (як RemOnline, BinoTel)
**Плюси:** Немає локального заліза, автоматичні оновлення, доступ з будь-якого місця
**Мінуси:** Повна залежність від інтернету, затримки, щомісячна підписка, дані у третіх осіб
**Вирішальний мінус:** Зупинка роботи при відсутності інтернету — неприйнятно

### Варіант B: Desktop App (Electron + SQLite)
**Плюси:** Офлайн, швидко, простий installer
**Мінуси:** Немає мережевого доступу з планшетів механіків, немає multi-user, обмежені можливості БД
**Вирішальний мінус:** Механіки не можуть підключитись з планшетів

### Варіант C: Local Server + Docker Compose (обрано) ✅
**Плюси:**
- Повна офлайн-незалежність
- Мережевий доступ у межах ЛАН (планшети механіків)
- PostgreSQL — повноцінна реляційна БД з транзакціями
- Docker ізолює всі залежності
- Один `docker compose up -d` запускає весь стек
- Cloud sync легко додається пізніше як опціональний модуль

**Мінуси:**
- Потрібен локальний сервер/ПК (мінімум Intel NUC або подібний, ~$500)
- Складніший installer ніж SaaS
- Оновлення потребують уваги (вирішено через Watchtower + Update.ps1)

## Рішення

**Обрано Варіант C: Local Server + Docker Compose**

### Деталі реалізації

```
┌──────────────────────────────────────────────┐
│  Локальний сервер Windows (Intel NUC або ПК)  │
│                                              │
│  Docker Compose Stack:                       │
│    api (NestJS)    ← бізнес-логіка           │
│    web (Next.js)   ← UI Reception + Admin    │
│    postgres        ← основна БД              │
│    redis           ← черги + кеш             │
│    minio           ← файли (фото, документи) │
│    caddy           ← reverse proxy + HTTPS   │
│                                              │
│  LAN 192.168.x.x                             │
│    ├── ПК приймальника  → http://sto.local   │
│    ├── Планшет механіка → Expo mobile app    │
│    └── ПК бухгалтера    → http://sto.local   │
└──────────────────────────────────────────────┘
```

### Мінімальні вимоги до сервера
- CPU: Intel Core i3 10-го покоління або AMD Ryzen 3 5000
- RAM: 8 GB (рекомендовано 16 GB)
- SSD: 256 GB (рекомендовано 512 GB)
- ОС: Windows 10 Pro / Windows 11 Pro / Windows Server 2019+
- Мережа: Ethernet у ЛАН (рекомендовано) або WiFi

## Наслідки

### Позитивні
- Система не зупиняється через збій провайдера
- Відгук ≤ 10ms (локальна мережа)
- Повний контроль над даними
- Немає щомісячних хмарних витрат для локальної роботи

### Негативні та їх вирішення
- **Потрібне залізо** → мінімальний бюджет ~$300 (вживаний NUC) або використання наявного ПК
- **Резервне копіювання** → `Backup.ps1` автоматично кожні 6 годин + зашифрований cloud backup (опц.)
- **Оновлення** → `Update.ps1` + Watchtower для автоматичного pull нових образів

## Тригер перегляду

Якщо > 50% клієнтів просять cloud-only варіант без локального сервера → розглянути Варіант A як окремий SKU.
